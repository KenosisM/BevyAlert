# 调研：FA2「框架模式」的盒子画法，以及地形图能不能按面拆开

日期 2026-10-17。目的：验证「悬崖是固定方盒子、可以枚举、可以切出顶面边缘和悬崖壁」这个思路，
并找出它跟 ra2engine 现有数据结构的接点。

---

## 一、框架模式的真身：按高度换一张固定的盒子图

界面上的「框架模式 [Ctrl+F]」内部名是 **MarbleMadness / FrameMode**：

- `Supplementary/FADialog.ini:369` → `40115=框架模式 [Ctrl+F]`
- `Supplementary/FALanguage_Chinese.ini:1517` → `MarbleMadnessNotLoaded=无法加载 marble.mix！框架模式将无法使用！`

它画东西的地方在 CIsoView 的取砖逻辑里，**核心只有两句**（`Ext/CIsoView/Body.DrawObjects.cpp:1779-1790`）：

```cpp
if (CFinalSunApp::Instance->FrameMode)
{
    if (CMapDataExt::TileData[tileIndex].FrameModeIndex < CMapDataExt::TileDataCount)
        tileIndex = CMapDataExt::TileData[tileIndex].FrameModeIndex;      // 有指定框架砖就用它
    else
        tileIndex = CMapDataExt::TileSet_starts[CMapDataExt::HeightBase] + cell->Height;  // 否则按高度取
}
```

同一段逻辑在 `Body.OnMouseMove.cpp:2018-2035` 又出现一次，并且那里多写了一句：
`MarbleTileSet = CINI::CurrentTheater->GetInteger(section, "MarbleMadness", -1);`

`HeightBase` 的定义（`Ext/CMapData/Body.cpp:3691`）：

```cpp
HeightBase = CINI::CurrentTheater->GetInteger("General", "HeightBase", -10);
```

**结论**：框架模式根本不看这一格是什么地形，只看它的 `Height` 数字，然后到
`HeightBase` 那个 TileSet 里取第 `Height` 张砖。也就是说：

> 地形外观是「高度 → 一张固定盒子图」的**有限枚举**。
> 高度 0 是一个扁盒子，高度 3 是一个高盒子，就这几张。

这印证了你的判断：悬崖确实是固定方盒子，不同朝向/不同高度各对应一张，可以枚举。

---

## 二、高度单位就是 15 像素

`Body.DrawObjects.cpp:1774-1809` 的 `getTileVirtualHeight`：

```cpp
return cell->Height - subTile.YMinusExY / 15;
```

`YMinusExY` 是 extra 图向上延伸的像素数。除以 15 得到高度单位。

这与我们 `terrain.rs` 里 `oy` 含 `−15·level` 完全对得上：**1 个高度层 = 15 屏幕像素**。

---

## 三、关键发现：TMP 文件本身就把「顶面」和「立起来的墙」分成了两块

这是本次调研最有用的结果，而且比「从悬崖图里切」更直接。

RA2 的 TMP 格式里，一块砖由**两段独立的像素块**组成（`src/tmp.rs:52-73`、`src/tmp.rs:130-176`）：

| 段 | 字段 | 含义 |
|---|---|---|
| 主图 | `x, y, cx, cy` + 像素 | 60×30 的**顶面菱形**（画在 60×30 矩形里，菱形只占 900/1800 像素） |
| extra | `x_extra, y_extra, cx_extra, cy_extra` + 像素 + 深度 | **立起来的那个面**：悬崖立面 / 坡道面 / 桥面 |

`src/costgrid.rs:250-253` 把偏移统一成相对主菱形左上角：

```rust
ti.ex_x.push(c.x_extra - c.x);
ti.ex_y.push(c.y_extra - c.y);
ti.ex_w.push(c.cx_extra);
ti.ex_h.push(c.cy_extra);
```

`src/costgrid.rs:144` 的注释原文：`每个变体里每个 cell 的 extra 像素（悬崖立面 / 坡道面 / 桥面）`

**所以不需要「切割」**：悬崖砖在图集里本来就是「顶面一张菱形 + 立面一张矩形」，
两者是分开存储的，只是现在的 `terrain_bake.rs` 把两段按屏幕位置烙在了同一张平面图上。

## 四、这改变了两件事

### 1. 不需要从 FA2 里找「盒子部位 ↔ 悬崖图部位」的对应表

框架模式只提供「高度 → 盒子编号」，它**没有**记录「这张悬崖砖的哪几个像素是顶面、
哪几个像素是侧壁」。那张表不存在，也不用去找——TMP 的两段结构本身就是答案。

### 2. 之前 mesh 方案漏像素的根因，可以定位到「几何用了矩形」

现状：地形几何是 **60×30 的矩形**，但矩形里只有菱形那 900 像素是真砖，另外 900 像素是
透明的（索引 0）。于是渲染要同时满足三件事才能点亮一个像素：

1. 三角形覆盖到它（矩形覆盖了全部 1800 像素的位置）
2. 纹理 alpha ≥ 0.5（菱形外的像素是 0 → 丢弃）
3. 深度测试通过

第 1 步已经把深度写进去了，第 2 步又把像素丢掉，第 3 步挡住别的砖进来 ——
这个像素就谁都没写，漏出清屏色。**缝是「漏」出来的，不是「叠」出来的。**

如果几何改成**菱形本身**（4 个顶点：上 `(30,0)`、右 `(60,15)`、下 `(30,30)`、左 `(0,15)`），
几何边界就和纹理有效边界重合，没有透明区，也就不需要 alpha 测试，这个漏就没了。

菱形是平行四边形（`(30,0)→(60,15)` 与 `(0,15)→(30,30)` 同向同长），
UV 可以做标准仿射映射，不会扭曲。

## 五、待验证（没有实测，不许当成已确认）

1. **菱形几何 + 关闭 MSAA 是否真的无缝**。推断是：相邻菱形共享边，像素归属由光栅化规则
   唯一确定，不漏也不重。但 4x MSAA 会让边缘像素半覆盖，可能渗出一圈淡线。
2. **extra 立面的几何位置怎么定**。数据给了 `(ex_x, ex_y)` 屏幕偏移，理论上可以用同一套
   屏幕↔世界换算把它落到竖直面上。但一块砖只有一个 extra 槽，一段完整悬崖要靠多块砖
   拼（不同朝向各一张），拼缝在几何上能不能严丝合缝，没验过。
3. **斜面（ramp）**。ramp 的 extra 是斜的，不是竖直的，不能当立面处理。
4. **原版地图里的 `FrameModeIndex` 表**在 FA2 的 exe 里（`CTileTypeInfo`），
   FA2sp 只是读取，源码里没有这张表的内容。我们要用的话得自己从 theater ini 推。
