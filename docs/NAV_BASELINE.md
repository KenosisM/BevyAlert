# 初始群体行为基线

这些数据保留初始移动系统的缺陷，作为导航、接触和停车改造的对照。
对应实现见 [初始演示 PR](https://github.com/KenosisM/BevyAlert/pull/3)，
它们是历史数据，后续导航修正会改变轨迹。
构建为 Windows x64、Rust 1.97.1、Dev（本包 opt-level=1），固定 60 Hz。
每例运行 3600 tick，即 60 秒模拟时间；完全对称，Seed=0、Jitter=0。

| 场景与模式 | 单位数 | 60 秒仍在移动 | 末态到指定旧目标的最大距离 | 采样端点最大重叠 |
|---|---:|---:|---:|---:|
| 四群交叉，旧连续 | 256 | 235 | 4.884 格 | 0.181188 格 |
| 同高度对穿，旧连续 | 128 | 120 | 4.947 格 | 0.179560 格 |
| 单群，旧连续 | 64 | 56 | 4.737 格 | 0.146505 格 |
| 四群交叉，旧离散 | 256 | 0 | 8.944 格 | 0.687744 格 |

移动计数使用速度大于 0.02 格/秒。距离只是对旧目标的观察，没有把它定义为
完成判定。旧连续系统在目标附近仍然运动；旧离散系统虽然停止，但距旧目标
仍然很远。两者的到达数和等待原因均为 `not-ready`，静止不能当作完成。
所有指令仍然活动，没有通过取消命令得到成功计数。

四群交叉的末态 digest 为 `ba3fae50a63a21bf`。从导出的 `.scene.ini` 重放后，
整个末态单位表逐字节相同。三档数量支持和一次 tick 的规模检查覆盖四群共
1024 和 4096；这些检查不表示千单位功能或性能验收通过。

复现命令与输出说明见 [四群演示](NAV_DEMO.md)。原始 CSV、单位末态与日志留在
调用者指定的本地输出目录，不纳入仓库。本表只保留必要的技术摘要。

观察每 60 tick 采样一次，重叠只检查采样端点，会漏掉 tick 内的轨迹错误。
阶段计时同样是稀疏 Dev 观察，不能代表所有 tick 的 P95/P99，也没有用于性能
达标结论。后续验收需要 Release、逐 tick 计时、连续轨迹检查和完整停车状态。
