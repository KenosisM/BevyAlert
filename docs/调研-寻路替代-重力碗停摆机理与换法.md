# 调研：重力碗在汇聚点停摆的机理，与四条替代路线

状态：**纯调研（2026-10-18）。没有改任何一行代码。**
读者：你。用来拍板「换不换、换哪块」。

---

## 0. 一句话结论

停摆不是常数没调好。它是**三条硬闸门**（碗底格数=车数 / 平地只准往前 / 动量耗尽就放弃）
加上**一条不可恢复性**（压死之后没有任何代码能让它再动）共同造成的**终态**。

任何只调参数的改法都只是把「什么时候定格」挪一挪，改不了「定格之后没人能救」。
要根治必须换运动模型（下半段），长程寻路（`costgrid` + 流场）可以留着。

---

## 1. 停摆的精确机理（代码级）

### 1.1 终态锁：碗底大小 = 车数

`play.rs:78`

```rust
let mut floor = well_floor_cells(&nav, &footprint, dest, n, head_x, head_y);
```

`n = sel.len()`。`nav.rs:727` 的 `well_floor_cells` 按「到点击处的整数平方距离」由近到远
逐格取，取满 `n` 格即止；同一环内按「离行进中线多远」破平局，多出来的从逃逸侧削掉。

这条设计的本意（上游 `nav.h` 注释）是：**碗底多一格就永远静不下来**——总有一格可挪，
于是永远有人在挪。所以「填满」和「停下」被绑成同一件事，一个刹车片都不留。

后果是它同时把**容量**也钉死了：

- **案例**：12 辆车点在一处 2 格宽的窄道口正中。碗底要取 12 格，但口子只容得下 2 格宽 × 4 格长
  = 8 格，再往外就是被侵蚀掉的不可走区。`well_floor_cells` 只能沿口子往两头排，凑够 12 格需要
  延伸 6 格。前 8 辆车顺墙滚下去把口子填满；后 4 辆车**在碗底之外**（`dist_at > 0`）就再也
  下不去了——它们前方的等代价格全被占，于是停在半坡上。这不是「排队」，是**永久停车**：
  它们的目标不是「排在后面」，而是「压根没有位置」。
- **案例**：40 辆车点在开阔地。碗底是恰好 40 格的圆盘，外围 6 辆车进不来，会停在圆盘外
  一圈的墙上或平地上，脸朝着人堆，永远不动。玩家的观感就是「一半兵不走了」。

### 1.2 平地只准「往前」——投影必须 ≥ 1

`world.rs:746`

```rust
let proj = ix * ox + iy * oy;
if proj < 1 {
    continue; // 只往前：不与之平齐，也不往后
}
```

`ix,iy` 是**它滚进碗底那一步的方向**（`u.enter_dx/enter_dy`），`(ox,oy)` 是候选格相对当前位置。
投影 `< 1` 的候选全部拒绝，也就是：**横向（projection = 0）与斜后（< 0）一律不走**。

- **案例**：8 辆车从北侧崖壁滚进碗底，把碗底北沿一整排占满。第 9 辆车滚到底边时，它正前方那格
  被占，而它**左、右两格是空的**。但左右两格投影 = 0 → `proj < 1` → 被拒。它只能等。
  前面那 8 辆里如果有一辆已经 `roll` 耗尽定格（见 1.3），这辆车就永远等下去。
  这就是玩家看到的「人堆边上那几辆明明旁边有空位，就是不走」。

### 1.3 `floor_parked`：动量耗尽就主动放弃

`world.rs:670`

```rust
let floor_parked = here <= 1e-6 && u.roll <= 0;
```

`here <= 1e-6` = 站在碗底格上。`u.roll <= 0` = 平地动量花完了。两者同时成立，这一步就
**不允许迈**（`world.rs:811` 的 `!floor_parked`），哪怕旁边有空格、哪怕它还没排好。

动量的来与去：

- **授予**：只有「从墙滚到平地的那一步」（`world.rs:848`）
  ```rust
  if on_floor_now && here > 1e-6 {
      u.roll = if u.ap_budget > 0 { u.ap_budget } else { K_ROLL_BUDGET };
  }
  ```
- **消耗**：只有「贴着一个已经定格（`roll <= 0`）的邻居、自己在等」时每 tick 扣 1（`world.rs:877`）。
- `K_ROLL_BUDGET = 999`（`world.rs:363`），`ap_budget = ceil(2.0 * 1200) = 2400`（`play.rs:84`）。

**这里有一处时代错配，值得单独记一笔：**

上游 `play.cpp` 按 1200 Hz 写的 `2.0 * 1200` = 2 秒。Rust 侧走 Bevy 的 `FixedUpdate`
（`game.rs:739`），**Bevy 默认 64 Hz，全工程没有任何一处 `set_timestep`**（已 grep 确认）。
于是同一个 2400 tick 变成 **37.5 秒**。

- **观感后果**：一次 40 车汇聚，前 2 秒之内正常，之后进入一段长达半分多钟的
  「轻微挤动、谁也没挪到位」的磨蹭期，然后突然全体定死 —— 因为 `roll` 在这一整段时间里
  被一个已经定格的邻居一格一格啃到 0。玩家看到的是「挤了半天最后乱成一团停住」。
- 这不是根因，但它把根因的观感放大了 18 倍。

### 1.4 八向 + 8° 转头门槛

`world.rs:827`

```rust
let faced = angle_gap(u.dir_angle, u.dir_target) <= K_FACE_TOL;
```

`K_FACE_TOL = 8.0`（`world.rs:359`），`turn_rate = 320 °/s`（`world.rs:439`）
→ 64 Hz 下每 tick 5° → **转 45° 要 9 tick（0.14 秒）**。八向移动意味着相邻两格之间常常正好
差 45°。密集队形里每换一次方向就多 9 tick 的停顿，40 辆车链式叠起来是很可观的排队时间。
这条不是错，是慢；但在 1.2 的「只准往前」之上，它会把「本来能挤过去」的时机一个个吃掉。

### 1.5 压死之后没有第二条路 —— 停摆是不可恢复的终态

`world.rs:883` 的注释自己写得很清楚：

> 还是卡着：有人站在它必须去的地方，也没有等代价的空格可滑。那就等 —— 是被压实，
> 不是被命令停下。这里什么都不解：还在下落的邻居会自己让开。

「还在下落的邻居会自己让开」这个前提，在 1.1 里不成立（碗底没位置给它落），在 1.3 里也不成立
（邻居已经 `floor_parked`）。于是这段代码在那些情形下等价于「永远原地不动」。

而全工程**没有任何一处**能把它救回来：

| 函数 | 本该干的事 | 跨文件调用次数 |
|---|---|---|
| `find_path_extra` | 带 `budget` 的局部重算（卡住时绕一下） | **0** |
| `smooth_path` | string-pull，把折线拉直 | **0** |
| `assign_formation_targets` | 最近优先认领 + 成对交换 uncrossing（**指派每辆车一个具体格**）| **0** |
| `detect_bottlenecks` | 认窄口 | **0** |
| `side_bias_grid` | 给窄口加代价，绕开人流 | **0** |
| `find_path_hierarchical` | 大图分层 A* | **0** |
| `path_from_flow_field` | 从流场抽一条具体路线 | **0** |
| `find_path` | 普通 A* | **0** |

（统计方式：`grep -rn <name> src/ --include=*.rs | grep -v '^src/nav.rs'`，全部为 0；
`nav.rs` 内部只有单测在调用它们。）

唯一能改变单位去向的门是 `play::issue_order_at`，而它只在玩家下指令时被调一次。
**压死之后，除了再点一次右键，逻辑上没有任何东西能让这辆车动。**

### 1.6 汇总

| # | 闸门 | 位置 | 触发条件 | 玩家看到什么 |
|---|---|---|---|---|
| 1 | 碗底格数 = 车数 | `play.rs:78` / `nav.rs:727` | 目的地容纳不下这么多车 | 一部分兵停在半路，永远不动 |
| 2 | 平地只准往前 | `world.rs:746` | 正前方被占，左右有空 | 旁边明明有空位就是不走 |
| 3 | 动量耗尽放弃 | `world.rs:670` | 碗底 + `roll<=0` | 挤了一会儿突然全体定死 |
| 4 | 转头门槛 | `world.rs:827` | 换向到非 45° 整数倍的过程 | 密集时一顿一顿 |
| 5 | **无重规划** | 全工程 | 上四条任一条触发 | **不可恢复** |

第 5 条才是真正致命的。前四条任何一条单独存在都不至于此——只要卡住时能「改去别处」。

## 2. 为什么调参数一定没用

| 想调的 | 调了会怎样 |
|---|---|
| `ap_budget` 调大 | 磨蹭期更长，压实得更紧、停的位置更乱 |
| `ap_budget` 调小 | 更早定格，观感更差 |
| `K_FACE_TOL` 放宽 | 会在斜向格之间切角，穿墙缝 |
| `well_floor_cells` 的 `n` 放大 | 上游注释自己写了：「碗底多一格就永远静不下来」 |
| `K_ROLL_BUDGET` | 同 `ap_budget` |

根因是：**所有决策都只回答「这一 tick 走不走」，没有一处回答「我该改去哪」。**
后者是「重规划」，本项目里所有重规划函数都是死的。

## 3. 四条替代路线

### 路线 A：补丁式（保留流场，只拆掉闸门）

改动集中在 `world.rs` + `play.rs`，不动 `nav.rs`。

1. **放开投影限制**：`proj < 1` 改成「不许回退到 `last_step`」即可，允许横向与斜后一步。
2. **溢出而不是压死**：碗底填满后，没格的车用 `nav::nearest_free_cell`（已存在，当前也是死代码）
   找一个**碗底之外**的最近空闲格当临时终点，`path` 直接接过去。这就是「排队」，而不是「停车」。
3. **给 `roll` 装一个下限语义**：`floor_parked` 从「绝对不许动」改成「不许**主动**动，但如果有空格
   就仍然走」——它现在就等于把单位冻住，而这个功能没有任何正面价值（真到位的车本来就没有空格可走）。
4. **顺手修 `ap_budget` 的 1200 → 64 时代错配**（改成按秒算，与 tick 率无关）。

- 工作量：**200–350 行**
- 风险：低。不动算法，只动三条判据。
- 修好什么：不再是永久定格；旁边有空位就会挪。
- **修不好什么**：还是**离散占格**，两辆车不能同时向一格挤、不能互相推开；队形仍然是「压出来的」
  而不是「排出来的」；窄口仍然会堵成长龙。做完之后你的评价很可能还是「不够理想」。
- 定位：**一次性止血**，不是终点。

### 路线 B：格位认领（经典 RTS 做法）

1. `issue_order_at`：碗底 N 格 → `assign_formation_targets`（已写好、已测、死代码）
   给每辆车指派**一个具体格**，最近优先认领 + 成对交换 uncrossing。
2. 每车 `find_path`（已写好、已测、死代码）+ `smooth_path`（同上）到自己那一格。
3. 每 tick 沿 `path` 走；下一格被占 → 等 `K` tick；超 `K` → `find_path_extra(budget)` 局部重算；
   再超 → `nearest_free_cell` 放弃原格改去最近空位。
4. **到达判定**：站到自己那一格 → `path.clear()`，进 idle。这是重力碗压根没有的东西。

- 工作量：**500–800 行**（主要是在 `world.rs` 写「腿部状态机 + 三级重规划闸门」）
- 风险：中。要动 `world.rs` 主循环，但用的全是 `nav.rs` 里已有的、已测的函数，不新增算法。
- 修好什么：会绕、会排队、队形**整齐**（因为位置是指派的，不是压出来的）；卡住能自愈。
- **修不好什么**：`occupied` 还是二值占格，**两车不能同格、不能挤压**。窄口 40 车过口子
  一定是一条长龙，且第二辆必须等第一辆完全离开才能进——这就是 RA2/OpenRA 的经典手感。
- 一句话：**这是「RA2 水平的正确」，不是「星际 2 水平」。**

### 路线 C：格子长程 + 连续空间局部避障（唯一能真正「挤过去」的）

1. 长程保留：`CostGrid` + 流场（或 A*）只回答「往哪个方向走」。
2. 短程换成连续坐标：`cell_x/cell_y` 不再吸附格心；每个 agent 有
   `desired_velocity = 长程方向 × speed`。
3. 邻居列表（按半径取前 K 个）→ **ORCA / RVO 半平面求解** → 得到实际速度 → 积分位置。
4. 最后把位置夹回可行走区（`CostGrid::walkable`），不合法就退回到「本 tick 走一半」。
5. **拆掉** `occupied` 二进制占格与 `claimed` 原子认领——它们和连续运动是互斥的两套模型。

- 工作量：**1000–1800 行**，其中 `world.rs` 的运动半段基本重写。
- 风险：高。`occupied` 现在可能被单位放置 / `pick_cell` / 建筑占地用到，要一起查。
- 修好什么：**这是唯一能做到「从人堆里挤过去、有人挡就绕、永不僵硬定格」的模型。**
  也是星际 2 的做法（它长程用 navmesh，短程用 boids 式转向 + 碰撞预测）。
- 代价：紧密度不可控（单位会互相挤开），移动观感会从「格子舞」变成「流体」——
  这不一定是你想要的 RA2 手感。

### 路线 D：移植

| 候选 | 规模 | 它有没有局部避障 | 值不值 |
|---|---|---|---|
| 0 A.D. `CCmpPathfinder.cpp` | 1500–2500 行 | **没有**（靠格位预留） | 搬完 ≈ 路线 B，但要背别人的架构 |
| Spring / Recoil `QTPFS` | 3000+ 行 | 部分（`MoveType` 里有推挤） | 耦合 `CommandAI`/`MoveType`，最痛 |
| Recast & Detour `DetourCrowd` | — | **有，而且就是 RVO** | 但它要 navmesh，RA2 是格子地形，要另做一套几何 |

- **DetourCrowd 是唯一现成的「解决汇聚停摆」的答案**（局部避障 + 路径跟随，专门为「一群人走同一条路」设计）。
  代价是必须先把地形三角化成 navmesh。对 RA2 这种等距格子地形，这是一整个子项目。
- **星际 2 本体没有源码可抄**。公开的只有 GDC 2011 的架构描述
  （Anhalt / Kring / Sturtevant, *AI Navigation: It's Not a Solved Problem Yet*）：
  约束 Delaunay 三角化 navmesh（地面 / 飞行 / 悬崖过渡分层）+ 三角图 A* + Boids 式转向 + 群体流场。
  可抄的是**架构**，不是代码。
- 结论：**三条都不划算**。路线 B 想要的东西自己写比搬快；路线 C 想要的东西没人现成给你。

## 4. 我的建议

| 你的目标 | 走哪条 |
|---|---|
| 只想「别再永久定格了」，先能玩 | **A**，一天量级 |
| 想要「像个正经 RTS，会绕会排队，队形整齐」 | **B** |
| 想要「人堆里能挤过去，不再僵硬」 | **C**，直接跳，别做 B 当中转站 |

**不建议做的**：把 A 和 B 都做一遍再上 C。B 做完你会发现还是离散占格，还得再推翻一次——
中间那 500–800 行是白写的。

如果你只能选一个，我建议 **C**。理由：你对现有实现的评价已经是「不够理想」，
而 A 和 B 的天花板就在这里——它们都受制于「一格只能站一个」。C 是唯一能突破这个天花板的。

## 5. 若走 C，具体要拆什么、留什么

**拆**

| 东西 | 位置 | 为什么 |
|---|---|---|
| `occupied`（格 → 车 tag） | `world.rs:526-548`、`SimEnv.occupied` | 二值占格与连续运动互斥 |
| `claimed`（本 tick 原子认领） | `world.rs:558-577` | 同上 |
| `committed`（腿交叉检测） | `world.rs:550-556` | 连续运动里没有「腿」 |
| `path` / `leg_t`（格到格走腿） | `world.rs:606-651` | 换成速度积分 |
| `roll` / `enter_dx,dy` / `floor_parked` | `world.rs:670,717,849-879` | 压实隐喻整个去掉 |
| `K_FACE_TOL` 硬门槛 | `world.rs:827` | 连续朝向不需要「没对准就不许动」 |

**留**

| 东西 | 用途 |
|---|---|
| `CostGrid` + `erode_grid` | 长程仍要它算可达与代价 |
| `compute_flow_field_cpu_multi` | 群体长程方向（一张共享场，无交叉，这个优点要保住） |
| `well_floor_cells` | 仍然是「一群人要去哪一块」，只是不再当刹车片 |
| `facing_octant` / `facing_angle_of` / `turn_toward` | 朝向照样要摆 |
| `GroundField::level_at/tilt_at` | 贴地与倾斜 |

**加**

```
每 tick，每 agent：
  1. 取长程方向 = 流场在其所在格的方向（或 A* 路径的切线）
  2. desired_v = 方向归一 × speed
  3. 邻居 = 半径 R 内最近的 K 个单位（K≈8）
  4. v = ORCA(desired_v, 邻居们)            // 半平面线性规划，~80 行
  5. pos += v * dt；再夹回 walkable 格
  6. 到了（到碗底格且速度趋零）→ idle
```

ORCA 的参考实现（RVO2 库）是 Apache 2.0，~1200 行 C++，直译成 Rust 大约 400–600 行。
它解决的就是「一群人朝同一点走、互相避让」这件事本身。

## 7. 实施记录（路线 C 已落地）

状态：**已实现并通过自测**。旧系统完整保留，用 `SimEnv::use_crowd` 切换（默认 `true`）。

### 新增 `src/crowd.rs`（连续运动层）

三层，对应「互斥力 + 路权 + 压力场解耦」：

| 层 | 位置 | 作用 |
|---|---|---|
| 长程方向 | `nav::FlowField`（没改） | 8 邻域最省格 → 单位方向；保住「一张场、流线不相交」 |
| 互斥力 | `step_agent` 的分离项 | 软推开，允许部分重叠，不再一格锁一辆 |
| 路权 | `Agent::priority = -剩余场距离` | 近终点者优先；让路者做横向偏转，占优者只做最小偏转 |
| 压力场（解耦） | `Pressure`（每 4 tick 重建一次） | 拥挤度标量场 → 梯度反向推开；**不进流场代价**，避免箭头每帧翻转 |
| 位置修正 | `resolve_overlaps`（PBD，2 轮） | 硬约束：把重叠圆盘直接推开，解决「速度层只能压到软重叠」 |

### 关键取舍（都是踩过才知道的）

1. **拥挤时要收油门**（`brake_crowd`）：否则期望速度一直往里顶，稳态距离落在 0.68（半径 0.45 ⇒ 明显半重叠）。
2. **站定的单位也必须吃分离力**：最初 `settled` 直接返回零速度，结果重叠被永久冻结 —— 和旧模型同一个病。
3. **速度层 + 位置层分离**：只靠力，稳态就是「力的平衡点」；硬约束必须单独一层。

### 自测契约（`cargo test --bin ra2engine crowd::`）

24 个单位从半径 12 的圆周向同一点收拢：

- 全部在 3.6 格内（密排理论半径 ≈2.3，实测 **2.86**）
- 静止后 30 tick 位移 < 0.35（**不抖**）
- 任意两车距离 > 0.75（半径 0.45 相切是 0.90，允许约 15% 视觉重叠）

### 后续两轮（已做）

**切向逃逸**（GPU-Crowd-Godot 的路权兜底）：`Unit` 加了 `stall_ticks / escape_ticks / escape_side`。
连续 30 tick「想走却没动成」→ 横着走 20 tick 绕开对头，方向按 `idx` 奇偶分左右（确定性，不用随机）。

**两段限幅**（Boids）：先按 `max_accel*dt` 截断速度变化量，再截断速度本身。
加速度上限取 `speed * 6.0`（6 倍速/秒，约 0.17 秒满速）。
**关键坑**：挤在一起时必须**关掉**加速度限幅 —— 否则在密集区反应被拖慢，
24 车收敛后仍会以 0.44 格/30tick 缓缓漂移。判据是「邻域内有 d < min_d 的人」。
