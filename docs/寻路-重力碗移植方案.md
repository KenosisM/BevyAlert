## 0. 结论：可以移植，前置已齐

寻路的唯一外部输入是 `CostGrid`（地图 → 可通行网格）。它**昨天刚在 Rust 侧完成并对齐**（`src/costgrid.rs`，五张真实地图与 `wwread nav` 零差异）。剩下的三块——`nav`（算法）、`world`（模拟）、`play`（指令链）——**全是纯逻辑**：无渲染、无 IO、无平台调用，是标准的「逐行对等搬运」对象。

> 注意：`world.cpp` / `nav.cpp` / `play.cpp` 里**没有一处 include rvo2**。`src/engine/rvo2/`（~1800 行第三方库）与本产品无关，是历史遗留，**不搬**。

## 2. 要搬的三块

### 2.1 `src/nav.rs` ← `nav.cpp` 全套（18 个函数，全是纯函数）

**格与朝向**
- `Cell`、`facingOctant(dx,dy)`、`facingAngleOf(dx,dy)`（等距投影后的 8 向角，0 = 东北）

**格网与足迹**
- `CostGrid`（含 `cutCorners`）、`Footprint`、`fits`、`erodeGrid`
  - 案例：一辆 1×1 车（`cutCorners=false`）面对对角空隙 → **不许切角**；步兵小于一格（`cutCorners=true`）→ 允许一侧被堵时走对角。`erodeGrid` 让宽单位在「比它窄的缝」上直接不可通行，而不是当成质点钻过去。

**A\***（两个重载）
- `findPath(g, from, to)`；`findPath(g, from, to, extraBlocked, budget)`
- 8 向、octile 启发、对角不许切堵角；`budget` 给局部重算封顶；对角两翼被动态阻挡也算被占

**流场**（本设计的核心）
- `computeFlowFieldCpu`（单源）、`computeFlowFieldCpuMulti`（**多源**）
  - 案例：编队被点了一个目标 → 上游不用「每车一条私路」，而是对**碗底所有格**做一次多源 Dijkstra，得到**一张**共享距离场；每个单位只读同一张场的箭头。两辆车读同一份箭头 → 路线是同一标量场的流线 → **天生不会互相穿越**。私路方案（n 次求解、n 张无关场）正是当年产生交叉与推挤的根因。
- `pathToNearestSource`、`pathFromFlowField`

**编队 / 碗底**
- `formationCells`（= `wellFloorCells(dir=0)`）、`wellFloorCells`
  - 案例：40 车点一处 → 碗底是**恰好 40 格**的圆盘（按欧氏平方距离逐格取），多余的从**逃逸侧**（沿朝向投影最大者）削掉。碗底多一格就永远静不下来（总有一格可挪）。
- `assignFormationTargets`（最近优先认领 + 成对交换 uncrossing）

**瓶颈与侧偏**
- `detectBottlenecks`、`sideBiasGrid`
- ⚠️ 现状：`detectBottlenecks` 的判据在真实地图上**尚未落地**（返回一堆 n=1 的假瓶颈，缺拓扑割检验）。按「照抄」纪律**先原样搬**，判据问题另行处理。

**其他**
- `smoothPath`（双向 string-pull，取拐点少者）、`buildBlockGraph` / `findPathHierarchical`（AHPA 风格分层，给单车跨大图用）
- 文件内 helper：`octile`、`lineClear`（Bresenham supercover）、`nearestFreeCell`

### 2.2 `src/world.rs` ← `world.cpp` 的**模拟半段**

搬：
- `Entity` 的**寻路字段**：`cellX/cellY/onGround/vx/vy`、`path/leg/legT/goal/lastStep`、`guide`(共享场)、`startDelay`、`roll`、`apBudget`、`enterDx/enterDy`、`dirAngle/dirTarget/turretAngle/turnRate/turretRate`、`cellZ/rampType/tiltPitch/tiltYaw/groundDirty`
- `World::update(dt)`、`World::rebuildOccupancy()`
- `GroundField`：`cellAtWorld / cellSurface / surfaceHeight` + `levelAt/bridgeAt/liftAt/rampAt/tiltAt`
- 帮助函数：`turnToward`、`angleGap`、`facingOctant` 依赖；常量 `kFaceTol=8`、`kRollBudget=999`、`kNeighX/Y`

`update` 的实现要点（照抄，勿简化）：
1. 先 `rebuildOccupancy()`；再建**本 tick 的 `claimed`**（保证同一格本 tick 只被一辆车认领）。
2. 先收集所有「正在走腿」的车 → `committedSteps`；两条腿若 `from+to` 之和相同就是**共享中点**（对角互换），必须拒绝。
3. 只预留**每个在途腿的下一个格心**（不是整条路线——整条预留会把别人饿死）。
4. 逐车（索引序）：非地面 → 直线积分；走腿中 → 推到对面格心（多格路线要重检「再下一格」是否被占）；站格心 → 读共享场 8 邻域：
   - 找 `bestAny`（最省，供转向）与 `bestFree`（最省且本 tick 空闲）；
   - 没有空闲格时：**平地**上按 `roll` 惯性横扫（投影最大、不许回头、不许爬高）；**墙上**允许等势滑步，但**必须**「落点自身还有一个更省的邻居」（`opensDown`），否则已静止的队形会沿等值线永远挪动。
   - 迈步门槛：`haveFree||sidestep`、`!floorParked`、不与他车腿交叉、`|angleGap(dirAngle,dirTarget)| <= 8`（**格心慢转**：没对准就原地转，不走）。
   - 迈步即写 `claimed`、`committedSteps`，并把 `occupied` 就地更新（让队首让出的格**本 tick 内**就能被后面顶上——这就是「后面的球推前面的球」）。
   - `roll`：从墙滚到平地的**那一步**授予 `apBudget`（否则 `kRollBudget`），并锁 `enterDx/enterDy`；只在「被**已停**的车挡住」时按 tick 扣 1。
5. 朝向：走腿中锁定步向；`turnToward(dirAngle, dirTarget, turnRate*dt)`；炮塔瞄 `goal`（`facingAngleOf`），速率更高。
6. 贴地：`levelAt/rampAt` 变化时更新 `cellZ/rampType` 并触发 `onGroundChange`（资产层重栅格化倾斜模型）。

不搬：`render()`、`anchorOf()`、`PartArt` / `UnitArt` / `hullFor/turretFor/tiltSetReady`、`makeVoxelGpuAssets`、`buildAxisTestVxl/CrossTestVxl/Palette`、`runWorldFrames/runSimDemo`。这些在 Rust 侧由 Bevy + `vxl_gpu.rs` 承担。

### 2.3 `src/play.rs` ← `play.cpp` 的**指令半段**

搬：`nearestUsable`、`issueOrderAt`
- 案例：点一个被建筑占住的格 → `nearestUsable` 环形外扩找最近可走格，命令仍然执行（而不是无视）。
- 案例：`issueOrderAt` 先用 `wellFloorCells` 按选中数铺碗底 → `solveMulti(floor)` 解**一张**场 → 每车 `guide=shared`、`goal=pathToNearestSource(...)`（只用来瞄准）、`startDelay` 按序号错开、`apBudget = ceil(2.0*1200)`。

不搬：窗口 / DIB / `blitToWindow` / `blitPart` / 相机 / `runPlay` 主循环 / PNG 输出 / 鼠标键盘（Bevy 侧）。
