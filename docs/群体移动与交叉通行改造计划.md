# Bevy 群体移动与交叉通行改造计划

日期：2026-10-30。实施工程：`D:\BevyAlert\BevyAlert`。

目标是交付一个可重复运行的 Bevy 演示：左右各两个单位集群同时出发，交叉换位，随后各自在目标区域停稳；同一套模拟还要支持大集群快速行进、展开和停车。推荐采用 **共享流场引导、预测式局部避障、集群让行、独占停靠点、停滞恢复** 的组合。

短暂减速和有序排队属于正常通行。成功标准是有路、有足够目标空间时能在规定时间内全部完成命令，期间不穿墙、不靠重叠挤过、不永久互相顶住，到达后不持续漂移。阵型在通行途中允许拉长、分流，到达后重新展开。

**首版场景与规模**

采用 192×160 格的平地，四个集群中心分别为 A 左上 `(32,40)`、B 左下 `(32,120)`、C 右上 `(160,40)`、D 右下 `(160,120)`。所有集群同一 tick 出发，A 与 D 交换位置，B 与 C 交换位置，四股交通在中央相遇。另设左右同高度对穿场景，单独检查迎面对撞。

| 用途 | 单位规模 | 要观察的行为 |
|---|---:|---|
| 行为开发 | 四群各 64，共 256 | 对称交叉、稳定选边、让行、准确停车 |
| 首轮主验收 | 四群各 256，共 1024 | 中央持续通行、四群全部到达、模拟耗时 |
| 大集群验收 | 单群 1024 | 起步、绕障、通过宽窄变化、目标区展开停车 |
| 扩展压测 | 四群各 1024，共 4096 | 容量上限、邻域退化、重规划队列与性能瓶颈 |

首版参数从现有单位尺度起步：半径 0.45 格、最高速度 6 格/秒、60 Hz 固定模拟；起点与停靠点间距先取 1.1 格。规模、坐标和阈值是本计划的建议初值，在实现前作为场景配置固定。4096 单位用于寻找扩展瓶颈，1024 单位作为首轮性能验收规模。

**当前实现与改造依据**

当前 `rulesmd.ini` 为 `Crowd=0`、`TickHz=60`，运行的是离散重力碗。`nav.rs` 已有 CPU 多源流场、A* 和带动态阻挡的局部搜索接口；`world.rs` 的实际迈步没有统一执行流场的禁止切角规则，也没有调用局部 A* 恢复堵塞。

`crowd.rs` 已提供连续位置、互斥力、压力场和重叠修正，但速度求解和位置修正仍扫描全队或全体单位对。`play.rs` 按最近流场种子给单位设置目标，多个单位可能拿到同一个目标；连续模式的重叠修正还存在将单位推入障碍后无法恢复的问题。

改造复用地图读取、`CostGrid`、地面高度和渲染链。集群共享流场用于降低长程寻路成本；不同集群的流场仍会相遇，同组单位也可能汇聚到同一处，因此不能据此推导出不会冲突或不会堵塞。

**移动系统的职责**

| 层次 | 具体责任 | 关键约束 |
|---|---|---|
| 指令与目标区 | 校验可达性、生成容量足够的停靠区、分配独占位置 | 接单失败、等待空间与到达必须是不同结果 |
| 长程导航 | 按集群、运动类型、目标区和地图版本缓存流场 | 同一移动代价和通行规则用于 A*、流场及实际移动 |
| 交通协调 | 对头选边、冲突期间固定路权、窄口分批放行 | 等待时间提高优先级，避免某一群长期被饿住 |
| 局部避障 | 根据期望速度与邻居预测未来碰撞，求可行速度 | 全体集群、移动单位、停靠单位和静态边界都参与 |
| 运动与接触处理 | 积分位置，检查完整移动轨迹，修正小量接触误差 | 使用原始合法位置；每次修正都重新检查墙体 |
| 到达与恢复 | 刹车、停靠、完成命令；停滞时让行或局部绕路 | 无进展不能被标记为到达，超搜索预算不能被当作无路 |

局部避障采用完整 ORCA 思路，参考 RVO2 的约束构造和求解：从外部给定的期望速度中选择满足碰撞约束的速度。ORCA 的职责是局部碰撞规避，本计划另外建立通行调度和进度恢复机制。[ORCA 作者说明](https://gamma.cs.unc.edu/ORCA/)、[RVO2 参考实现](https://github.com/snape/RVO2)。

首版以连续二维圆盘表示单位。期望速度先按驾驶需要平滑，实际速度由避障约束决定，车身朝向随后平滑跟随。紧急避让允许快速改变速度；如后续要求严格加速度或最小转弯半径，必须把可达速度限制纳入求解，不能在 ORCA 求解之后随意裁剪或旋转其输出。

移动中的单位默认对称承担避让责任；已停靠单位按不主动避让的障碍处理，经过它的单位承担完整避让责任。路权主要改变期望路线、让行点和放行时机，不采用每帧跳变的推力权重。

**实施顺序与阶段出口**

1. **恢复构建，建立同一套模拟的演示与无头入口。**

   构建环境与依赖恢复统一见 [Rust / Bevy 构建说明](BUILD.md)：Rust/Cargo 固定为 1.97.1，Bevy 固定为官方 Git revision `6d7f0b30939d7dcc24fdde113716d194997ea8d3`（0.20.0-dev），使用仓库内的锁文件。原来的 `bevy = { path = ".." }` 所指父目录源码没有随工程保存，不再作为新环境的前提。构建使用明确路径的 Cargo 命令，或调用共用安全构建入口的批处理；构建入口不自动清理编译产物。

   拟增加 `nav-demo` 入口，用四色简化单位展示四群交叉，支持重置、暂停、单步和规模切换。把正式移动逻辑收敛为一份固定步长模拟接口，无头测试与 Bevy 窗口调用它；演示不得另写一套简化寻路。记录到达数、等待原因、最长无进展时间、接触错误和每 tick 耗时。

   阶段出口：同一场景、同一随机种子在同一构建中可重复运行；能从日志确认当前使用哪套移动系统，能保存旧系统的行为基线。

2. **统一导航与碰撞规则，先让单个单位走对。**

   在 `nav.rs` 建立统一的相邻步通行和代价接口，处理边界、切角、单位尺寸和静态障碍。流场反向传播、方向提取和 A* 必须采用同一有向移动代价；用加权小地图对照最短代价，避免入口成本与出口成本混用。实际移动使用合法方向或合法候选边，不能只挑邻居距离最小值。

   连续移动增加带单位半径的轨迹碰撞检测，检查从旧位置到新位置经过的空间。修复重叠投影后的墙体处理，保存合法旧位置并执行受约束的修正。墙角、窄缝、地图边缘和高速跨格都必须覆盖。

   阶段出口：单单位能绕墙、过合法窄缝、拒绝封闭夹角；不可达返回明确失败；流场与 A* 的代价及可达性一致。

3. **实现停靠点分配与完整到达状态。**

   把点击解释为一个具有容量的目标区域。生成位于可达连通区域、满足单位半径和间距要求的停靠点，并维护跨集群的预约表；重新下令或取消时释放旧预约。换位场景要区分正在离开的旧占位者与已经停稳的占位者。

   命令发出时预约整组目标区，并采用保持空间顺序的分区、排序配对，再做局部交换优化，减少同组路线交叉。行进阶段共享流场，进入目标区后冻结各自停靠点，切到短距离引导；局部有障碍时使用短路径。只有位置失效才重新配对，不能逐帧交换目标。优先安排先到的单位填目标区深处，保留后续单位的进入通道；途中允许阵型变形。

   增加 `Moving → Arriving → Settled`，以及独立的 `Yielding / Replanning / Blocked` 状态。按剩余距离及制动能力减速；达到位置和速度阈值并保持一段时间后才完成命令。进入与离开停靠状态使用不同阈值，防止边缘反复切换。已停靠单位保持零期望速度，位置修正只处理数值误差；确需让路时由明确的让行任务唤醒。

   阶段出口：单群 64、256 个单位分别移动并停稳，没有抢同一停靠点、前排堵住后排或持续向中心挤压。目标区不足时扩大到合法空间，或报告等待/失败，不把剩余单位压进已满区域。

4. **接入预测避障，并消除全队两两扫描。**

   建立空间分桶，统一用于避障、接触检测和附近停靠点查询；近邻按稳定 ID 排序。查询范围根据速度、预测时域和半径确定，不能只因采用分桶就固定查询九宫格。统计邻居数量及截断次数；紧邻接触对象不能被上限过滤。RVO2 参数文档明确指出，邻居数量或查询距离过小会影响安全性。[RVO2 参数说明](https://gamma.cs.unc.edu/RVO2/documentation/2.0/params.html)。

   按 RVO2 参考实现移植并验证完整的单位与静态障碍约束、可行速度求解及不可行处理，保留许可信息。拥挤度可调整期望速度；避障完成后的积分仍执行连续碰撞复核。接触投影只修正小误差，不能成为靠相互推挤前进的主要手段。

   阶段出口：两单位对头、两队迎面和四群各 64 的开阔交叉通过；没有固定左右反复横跳、明显穿插或穿墙。性能记录能区分近邻构建、避障求解和接触处理。

5. **增加集群通行规则与停滞恢复。**

   开阔交叉采用统一靠右偏好；一次相遇期间保持选边，避免逐帧左右翻转。冲突区域的路权在一段通行批次内固定，以等待时长和稳定集群 ID 决定先后。狭窄通道设置入口等待区、方向占用和有上限的批次，保证先进入的一批能驶出，再切换方向；排队不能堵住出口。

   停滞检测同时观察一段时间内的路线进展、位移和等待原因。持续抖动但没有前进也算无进展。首版先以约 1 秒无进展触发诊断，随后依次尝试保持选边的让行、到局部让行点、带预算 A* 绕行、重新申请通行或停靠点。允许恢复路径暂时远离目标。移动单位不能全部永久写成硬墙；短期预约与已确定的静态占位分开处理。

   重规划使用统一队列、展开预算和冷却时间，每 tick 限额执行；超预算继续排队。所有超时以秒定义。等待有到期检查与公平性指标，不能无限刷新让行状态来掩盖未完成命令。

   阶段出口：四群各 256 的同步交叉全部完成；单车阻挡、T 字路口、窄桥对向交通都能绕过或有序通过。不可达和目标容量不足能给出明确结果。

6. **优化千单位吞吐，并接回真实地图。**

   固定模拟次序为：接收命令 → 快照和近邻索引 → 通行决策 → 期望速度 → 避障求解 → 积分与接触检查 → 到达/停滞判定 → 写回 ECS。并行计算从同一快照读入，保持必要的结果排序；碰撞修正采用明确、可重复的处理顺序。

   复用缓冲区，取消逐 tick 文件开关和高频全量日志，把渲染插值与固定模拟分开。每组长程场按目标和地图版本缓存；异步或分帧计算的结果附带命令版本，过期结果不得覆盖新指令。模拟和全图寻路分别计时，限制单帧重算峰值。

   完成四群合计 1024、单群 1024 和 4096 扩展压测后，在真实地图复测建筑绕行、坡道、窄口和重复下令。确认导航可通行边与地形边界一致，再把连续系统设为默认运行模式。

   阶段出口：1024 单位达到下列验收线；输出可复现的场景配置、计时结果和录像。4096 的实际能力由测量给出，后续根据热点决定是否需要分层流场、更多并行或 GPU 计算。

**首版验收标准**

以下是实现目标，不是当前实测成绩。记录测试 CPU、构建版本和场景配置，使用 Release 构建、60 Hz 固定模拟。每个主场景运行完全对称的固定布局，再运行 20 组固定种子的轻微位置扰动；不得只挑顺利的一次。

`T95` 为发出命令到 95% 单位进入 `Settled` 的时间，`T100` 为全部单位进入 `Settled` 的时间。四群交叉的无冲突基准，是四个集群分别单独完成同一路线的测量，取各群对应完成时间的最大值；保留同组避障、相同速度和停车条件。

| 指标 | 首版验收线 |
|---|---|
| 四群交叉完成度 | 四群各 256，目标区有容量，所有固定测试均 100% 到达；不能把等待或放弃计入到达 |
| 交叉效率 | 固定开阔场景的 `T95` 不超过无冲突基准的 1.8 倍，`T100` 不超过基准的 2.5 倍 |
| 大集群移动 | 单群 1024 在开阔地、绕障和宽窄变化场景全部完成；分别记录基准与增加的排队时间 |
| 停车稳定性 | 到达判定初值：离独占停靠点 ≤0.15 格、速度 ≤0.05 格/秒，连续保持 0.5 秒；随后无新指令和让行任务时，3 秒内最大漂移 ≤0.05 格 |
| 墙体与单位碰撞 | 无非法切角、穿墙或单位互相穿越；单位间最大数值穿透 ≤0.02 格，检查 tick 内轨迹而不只看终点 |
| 堵塞恢复 | 人为放置阻挡且保留绕路时，2 秒内进入明确的让行/重规划处理；最终完成命令，不能靠重置计时器通过测试 |
| 窄口公平性 | 两侧等待者都能获得通行；完成一次方向放行后评估等待方，不能无限追加同向单位导致另一侧饿死 |
| 模拟性能 | 1024 单位的模拟 tick 耗时 P95 ≤8 ms；记录中位数、P99、最大值及寻路重算峰值，避免平均值掩盖卡顿 |
| 演示流畅度 | 在记录的测试机器上，四色简化场景目标 60 FPS；真实地图另计渲染耗时，不能用降低模拟频率掩盖性能不足 |

失败时保留场景种子、状态快照和原因分类，定位是容量、路线、交通调度、避障、停车还是性能问题。无头断言与可视化演示必须使用正式 Rust 模拟代码。
