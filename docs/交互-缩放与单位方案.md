# 交互还原：缩放 / 单位选择 / 绘制单位

**来源**：`RA2REASM/src/engine/play.cpp`（`runPlay` 交互式窗口）、`src/engine/world.cpp`
（`anchorOf` / `render`）、`src/tools/wwread.cpp::cmdPlay`。
**现状（Rust）**：`game.rs` 是固定构图、无缩放；左键只下指令；单位是红色 `Cuboid` 占位。

## 1. 缩放（C++ 的 `Play::zoom`）

### 照抄对象
```cpp
int screenX(const Play& p, float wx) { return (int)std::lround((wx - p.camX) * p.zoom); }
int screenY(const Play& p, float wy) { return (int)std::lround((wy - p.camY) * p.zoom); }
```
（`play.cpp:57-58`）

| 项 | C++ | 出处 |
|---|---|---|
| 缩放范围 | `clamp(0.35, 2.5)` | `step` :277 |
| 滚轮步进 | `zoom *= pow(1.18, wheel)` | `step` :277 |
| 平移速度 | `760.0f / zoom` 世界像素/秒 | `step` :272 |
| 平移来源 | WASD/方向键 + **鼠标贴屏幕边缘**（`kEdge`） | `step` :268-274 |
| 边界 | `clampCamera`：视图不许超出地图 | `clampCamera` :138-145 |
| 初始构图 | `frameUnits`：按选中单位包围盒居中（y 再抬 55px，让模型不被地面切） | `frameUnits` :530-546 |

### Rust 侧方案
- 相机仍是现在这个**正交 2:1 等距**；缩放 = 改 `OrthographicProjection` 的
  `min_width/min_height`：`min_w = 窗口宽 / px_per_unit`，而 `px_per_unit = (cell_px/√2) * zoom`
  （`cell_px` 默认 60 ⇒ 未缩放时 1 格 = 60 屏幕像素，与 RA2 一致）。
- 平移：`cam_at += pan * (760.0 / px_per_unit) * dt`，沿相机的屏幕右/下基
  （`CAM_RIGHT` / `-CAM_UP`）。
- 边界：把 `cam_at` 限制在地图包围盒内（照 `clampCamera`）。
- 新增 `Zoom` resource + 一个 `Update` 系统读 `MouseWheel` / `ButtonInput<KeyCode>`。

## 3. 绘制单位（C++）

### 照抄对象
`World::render` :844 → 每个 entity 走两条路之一：
- **GPU**（默认）：`p.gpu->begin/setView(Camera{camX,camY,zoom,W,H})` + `world->render(gpu)`
  → 光线投射（`shaders/vxl_raycast.wgsl` 就是从它的 HLSL 转译来的）→ composite。
- **baked sprites**（回退）：`blitPart(hullFor(rampType), dirAngle, px, py)` +
  `blitPart(turretFor(rampType), turretAngle, px, py)`（:400-401）。
  `PartArt`（`world.h:37-54`）= 每个单位类型烘 **n 个朝向**的裁剪精灵 + `refX/refY` 注册点；
  车体与炮塔**分开烘**，各自按自己的角度取。

单位位置来自 `anchorOf`（`world.cpp:823-842`）：
```
dx = cellX - cellY + (mapWidth - 1)
dy = cellX + cellY - (mapWidth + 1)
px = (dx + 1) * pitchX
py = (dy + 1) * pitchY - surfaceHeight(cellX, cellY)
```
即**格坐标 → 等距世界像素**，高度已扣掉。Rust 现在缺这个函数。

### Rust 侧：三种接法（**要拍板**）
| | 做法 | 优 | 劣 |
|---|---|---|---|
| **A** | 用现有 `vxl_gpu.rs` 的 WGSL 光线投射，**离线**把每单位×朝向烘成图集，Bevy 里当 Sprite 贴（= C++ 的 baked 路径） | 最简单、立刻能看到；和 C++ 回退路径对等；复用已验证代码 | 朝向离散；没有实时坡面倾斜 |
| **B** | 把 `vxl_raycast.wgsl` 接成 **Bevy 的 render node**（实时光线投射） | 与 C++ 默认路径对等；朝向连续、可带坡面倾斜 | 工程量最大；Bevy render graph 要新学 |
| **C** | VXL 体素 → **表面 mesh**，用 Bevy PBR 渲染 | 完全融入 Bevy；光照/阴影现成 | 体素多时 mesh 大；每体素颜色要进 vertex color；和 RA2 的观感会有差 |

**我的倾向：先 A 后 B**（A 能马上看到单位，且是照抄；B 作为后续升级）。但这条你定。

## 4. 还缺的基础件（Rust）

- `world::anchor_of(cellX, cellY) -> (px, py)`：格 → 等距世界像素（照 `anchorOf`）。
  现在 `game.rs::sync_units` 用的是"格坐标 + 相机投影"，位置对，但没有这个**世界像素**口径，
  做选择/框选/缩放会对不上。
- 单位朝向：`Entity.dirAngle` / `turretAngle` / `rampType`（C++ 有；Rust 的 `world::Unit` 要补）。
